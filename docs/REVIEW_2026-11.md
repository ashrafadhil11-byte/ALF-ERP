# Project review — November 2026

What is missing, loose, or worth adding next. Checked: every API route, the pages, the 23 migrations,
the roadmap, and Supabase's own security and performance checks on the live database.

## 1. Fix soon (small, safety)
| # | Finding | Why it matters | Fix |
|---|---|---|---|
| 1 | Tables `employees` and `branches` have a "any signed-in user can read" rule in the database. | `employees` holds PIN hashes, civil IDs, dates of birth. The app never reads the database from the browser, so today this is not reachable through the app — but anyone with a login token and the project's public key could read every row. | Drop the two rules (the app's server uses its own key and does not need them). One small migration. |
| 2 | Login says "Username not found" for a wrong username. | Tells an outsider which usernames exist. | Same message for wrong user or wrong password. |
| 3 | No lock after many wrong passwords on the login page. | Password guessing (Supabase limits by IP only). | Lock the username for 15 min after 5 wrong tries (like the warehouse PIN). |
| 4 | Supabase "leaked password protection" is off. | Staff can choose passwords known from data leaks. | One switch in Supabase → Authentication → Passwords (you do this in the dashboard). |
| 5 | No automatic test run before a deploy. | A push goes live even if tests fail. | GitHub Action: run the 131 server tests, page tests and build on every push. |

## 2. Forgotten / half done
- **Push notifications when the app is closed.** Messages now chime and pop up while any ERP tab is open (also in the background). A notification when the browser or the installed app is fully closed needs Web Push: a subscriptions table, a sender on the server, and two secret keys (VAPID) set by you in Vercel.
- **Cargo after it leaves Oman.** Stock ends when boxes are handed to the forwarding agent. Arrival at a destination branch (if you run one, e.g. Kerala) is not tracked as stock there.
- **Old pages.** The 15 old `admin/*.html` pages and their menu script are still in the project, but every link now goes to the new app. They can be removed (less to maintain, smaller deploy).
- **Unindexed links in the database** (25). Fine with today's data; add indexes before volume grows (one migration).
- **Error alerts.** Server errors only go to the Vercel log. A daily "things that failed" summary (carrier sync, failed saves) to super admin via the bell or chat would catch problems early.
